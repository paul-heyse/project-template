# Discover library capabilities worth investigating

Start from the selected library family and repository objective. Read the relevant architecture
owner and representative local consumers. A concrete codebase opportunity ID is optional.
Use the [discovery and evidence guide](../../../docs/library_leverage/references/discovery-and-evidence.md)
to distinguish release capabilities, dependency selection, installation, source observations and
runtime evidence. Use prepared tools and existing records. Representative reads suffice when
generated or installed evidence is unavailable.

Maintain discovery briefings in the family's [library account](../../../docs/library_leverage/libraries/README.md#library-led-briefings).
Use `briefing.md` as the entry point. It may contain the complete discovery or summarize and
link to focused briefings under `briefings/`. Choose the organization, document boundaries and
level of detail that sufficiently explain the opportunities, without a fixed segmentation scheme
or document count. When using multiple briefings, use the summary to connect their findings,
explain research priorities across topics and identify useful compositions. Focused briefings
carry supporting analysis and enough context for selective reading.

Map capabilities to actual local uses, then look beyond familiar entry points to configuration,
extension points and companion packages. Give each shortlisted direction a concrete mechanism,
potential value, a condition that could defeat it and the next question that would distinguish
the possibilities. Include reasons to keep the current approach where they matter. Use relevant
[opportunity patterns](../../../docs/library_leverage/README.md) to sharpen the search.

Refresh the discovery account in place, keeping the summary and affected focused briefings
consistent. Record the inspected source and environment, relevant worktree changes, evidence
dates and coverage limits. Link shared context where appropriate and make differing dates or
source conditions explicit. Keep inherited evidence dated as originally gathered.
Link to reusable library types for detailed contracts and leave broad overviews repository-agnostic.

The discovery account owns contextual usage interpretation and proposed research priorities. Use
`leverage-codebase-audit` when a concrete responsibility deserves investigation,
`leverage-library-assessment` to establish contextual fit, and `leverage-opportunity-review` to
compare complete options. Follow the [framework](../../../docs/library_leverage/library-leverage-framework.md)
for those handoffs. Write research documentation within the assigned scope. Dependency adoption,
product changes and scheduling follow their existing authorization routes.
